🍳 Install TablePlan

TablePlan is a self-hosted household kitchen app. It handles recipes from links and screenshots, auto-generated meal plans, a pantry that tracks real use-by dates, and grocery lists you can email or print. It runs on your own server as a single app: one container, one data folder.

TablePlan is a single app

Recipes, photos, meal plans, shopping lists and your pantry are all stored by TablePlan itself. There's no separate recipe server, database or extra account to set up.

Tick each step as you finish it. Your progress is saved in this browser.

What's new

  • Two recipe styles: Classic or Step-by-step, tuned to your stove (gas, electric or induction) and oven (conventional or convection).
  • Cook mode with built-in timers.

What you need

🖥️ A server with DockerZimaOS, CasaOS, Ubuntu/Debian, a NAS, or a Raspberry Pi 4/5. Both Intel/AMD (amd64) and ARM (arm64) work.
💾 A few hundred MB of RAMPlus some disk space. Your recipes and photos take more space over time.
🔌 Port 9930TablePlan's web address. You can change it.

Optional:

  • An OpenAI API key to import recipes from screenshots, photos and video links. It costs a few cents per recipe.
  • An email account that allows SMTP, such as Gmail with an App Password, to email yourself lists and plans.

1 Install

Choose the method that matches your server.

ZimaOS (App Store, recommended)

  1. Open App Store → Community store → Add, and paste:
community store URL
https://thomasjvalenzuela.github.io/tableplan/store.json
  1. Switch to the TablePlan store and click TablePlan → Install.
  2. Optional: before installing, change the volume path if you keep app data on a different disk. The default is /DATA/AppData/tableplan/data.

ZimaOS shows an Update button whenever a new version is released.

Any Linux server with Docker (one command)

This covers CasaOS, Ubuntu/Debian and similar. SSH into the server and run:

on the server
curl -fsSL https://thomasjvalenzuela.github.io/tableplan/install.sh | sudo bash

The installer:

  • checks Docker and that port 9930 is free
  • picks an install folder: /media/DATA/AppData/tableplan, /DATA/AppData/tableplan or /opt/tableplan, whichever exists
  • starts the TablePlan container
  • prints the address to open

You can choose a different port or folder:

custom ports / folder
curl -fsSL https://thomasjvalenzuela.github.io/tableplan/install.sh | sudo TABLEPLAN_PORT=8930 TABLEPLAN_DIR=/srv/tableplan bash
Want to read it first?

It's a good habit to read a script before piping it to sudo. Download it and read it first:
curl -fsSLO https://thomasjvalenzuela.github.io/tableplan/install.sh && less install.sh && sudo bash install.sh

Docker Compose / Portainer / Dockge / Unraid

terminal
mkdir tableplan && cd tableplan
curl -fsSLO https://thomasjvalenzuela.github.io/tableplan/docker-compose.yml
nano docker-compose.yml        # optional: set TZ, change the port
docker compose up -d

In Portainer, go to Stacks → Add stack and paste the contents of docker-compose.yml.

The first download takes a minute or two. Wait for the container to show Running or healthy.

Coming from Mealie?

You can bring everything over in one go:

  1. In TablePlan, open Settings → Advanced → Import from Mealie.
  2. Enter your Mealie address (for example http://192.168.1.50:9925, using the server's network IP, not localhost) and an API token. Create one in Mealie under Profile → API Tokens.
  3. Tap Import. TablePlan copies your recipes, photos, favorites, meal plans and shopping lists.

It's safe to run more than once, and you can uninstall Mealie afterwards.

Used TablePlan v0.3 or earlier? Those versions ran a bundled Mealie. The one-command installer leaves it running after the upgrade so you can import from it (it prints the address), and sudo tableplan update removes it once you're done. If your update already removed it (for example on ZimaOS), its files are still in the mealie folder of your install. Start it again temporarily, import, then remove it:

temporary Mealie for importing
sudo docker run -d --name old-mealie -p 9925:9000 -v /DATA/AppData/tableplan/mealie:/app/data ghcr.io/mealie-recipes/mealie:v3.30.0
# import from http://YOUR-SERVER-IP:9925, then:
sudo docker rm -f old-mealie

Backup & uninstall

Everything (recipes, photos, plans, lists, pantry, settings and shelf-life rules) lives in one folder, data/. Back it up.

installer users
sudo tableplan backup      # writes tableplan-backup-DATE.tgz next to the install folder
sudo tableplan uninstall   # removes containers, keeps your data
compose users
docker compose stop && tar czf tableplan-backup.tgz data && docker compose start
docker compose down        # uninstall; delete the folder to remove data too

HTTPS & using it away from home

Chrome labels every http:// address as Not secure, including apps on your own Wi-Fi. TablePlan works fine at home without HTTPS. Adding it gives you a padlock and encrypted traffic.

Option 1: Tailscale (easiest, works away from home too)

  1. Install Tailscale on the server (it's in the ZimaOS App Store) and on your phones, and sign in to the same account.
  2. In the Tailscale admin console → DNS, turn on MagicDNS and HTTPS Certificates.
  3. On the server, run:
on the server (ZimaOS / CasaOS)
sudo docker exec tailscale tailscale serve --bg 9930
  1. Open https://<server-name>.<your-tailnet>.ts.net, which now shows a padlock.

Option 2: your own domain + reverse proxy

Use Nginx Proxy Manager, Caddy or Traefik:

  1. Point tableplan.example.com at the server's local IP. On Cloudflare, use DNS only.
  2. Proxy it to port 9930.
  3. Get Let's Encrypt certificates with the DNS challenge, so no ports need to be opened on your router.
Live barcode scanning needs HTTPS

Browsers only allow camera access on secure addresses. On plain http://, the pantry scanner falls back to taking a photo of the barcode or typing the number.

Never port-forward 9930 straight to the internet. If TablePlan is reachable from outside your home, set TABLEPLAN_PUBLIC=1 on the TablePlan container. Sign-in is then always required, and until you set a household password, you need the one-time setup code printed in the TablePlan log (ZimaOS → TablePlan → Logs, or docker logs tableplan).

FAQ

Does my data leave my server?
No, with two exceptions you turn on yourself: screenshot imports go to OpenAI, and emails go through your mail provider. The only other outside requests are one download of the public USDA FoodKeeper shelf-life database and a version check against GitHub Pages.

Where do the use-by dates come from?
From the USDA FoodKeeper database, always using the low end of its ranges to stay safe. When you open or freeze something, it switches to the matching "after opening" or "freezer" time. A date you type from the package always wins. You can edit any rule in Settings.

Do I need Mealie?
No. TablePlan stores everything itself. If you used Mealie before, see Coming from Mealie? to copy your recipes over.

What does it cost?
TablePlan is free and open source. AI imports use your own OpenAI account, at a few cents per recipe.
